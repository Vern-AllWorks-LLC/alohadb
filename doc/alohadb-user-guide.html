What is AlohaDB?

AlohaDB is a PostgreSQL 18-based analytical and AI-native database platform developed by Vern AllWorks LLC. It extends PostgreSQL with over 34 production-grade extensions covering vector search, geospatial queries, ML model management, cloud object storage, ontology-driven context search, ETL pipelines, streaming data ingestion, and Python-in-database execution.

AlohaDB is a drop-in replacement for PostgreSQL 18. Every standard PostgreSQL client driver, tool, and query works without modification. Extensions are optional and loaded individually with CREATE EXTENSION.

Architecture

AlohaDB follows the standard PostgreSQL extension model:

  • Each extension ships a .control file, one or more .sql install scripts, and a shared library (.so / .dll / .dylib).
  • Extensions that require background processing (cron, pipeline, kafka) register a background worker via shared_preload_libraries.
  • Extensions that rely on in-database Python use PostgreSQL's built-in plpython3u procedural language.
  • All algorithms use open standards with prior art predating any applicable patent window. HNSW (US10380099) is deliberately not implemented; IVFFlat (Lloyd's k-means 1957, inverted index 1960s) is used instead.

Extension Reference

pg_parquetio v1.1

Read Parquet, CSV, and JSON files directly from SQL. Version 1.1 adds a full Parquet column reader supporting PLAIN and PLAIN_DICTIONARY encoding with UNCOMPRESSED and SNAPPY compression.

Install

CREATE EXTENSION pg_parquetio;
-- or upgrade from 1.0:
ALTER EXTENSION pg_parquetio UPDATE TO '1.1';

Functions

FunctionReturnsDescription
read_parquet(file_path text, options jsonb DEFAULT '{}')SETOF jsonbRead a Parquet file; returns one jsonb row per data row
read_csv(file_path text, delimiter text DEFAULT ',', has_header bool DEFAULT true)SETOF jsonbRead a CSV file
read_json(file_path text)SETOF jsonbRead a newline-delimited JSON file

Configuration

-- Allow reads from specific directories
SET pg_parquetio.allowed_paths = '/data/files,/tmp';

Examples

-- Read a Parquet file into a table
CREATE TABLE sales AS
SELECT
    (row->>'product_id')::int    AS product_id,
    (row->>'revenue')::numeric   AS revenue,
    (row->>'sale_date')::date    AS sale_date
FROM read_parquet('/data/sales.parquet');

-- Query a CSV file directly
SELECT row->>'name' AS name,
       (row->>'age')::int AS age
FROM   read_csv('/data/users.csv')
WHERE  (row->>'country') = 'US'
ORDER BY (row->>'age')::int DESC
LIMIT  10;

-- Read JSON and aggregate
SELECT (row->>'category') AS cat, count(*) AS n
FROM   read_json('/data/events.jsonl')
GROUP  BY 1
ORDER  BY 2 DESC;
Note For complex nested or repeated Parquet schemas, use libarrow directly via the pg_cdc_arrow extension. read_parquet supports flat schemas only.

pg_vector v1.0

Dense vector type and IVFFlat approximate nearest-neighbor (ANN) search. Uses Lloyd's k-means (1957/1982) and inverted-file indexing — both prior-art algorithms with no active patent encumbrances. HNSW (US10380099) is intentionally not implemented.

Install

CREATE EXTENSION pg_vector;

Type

The vector type stores a fixed-length array of single-precision floats. Text format: [f1,f2,...,fn].

Operators and Functions

Operator / FunctionDescription
a <-> bL2 (Euclidean) distance
a <=> bCosine distance (1 − similarity)
a <#> bNegative inner product (for max-IP search)
vector_dims(v)Number of dimensions
vector_l2_distance(a,b)L2 distance (function form)
vector_cosine_distance(a,b)Cosine distance (function form)
vector_neg_dot_product(a,b)Negative dot product (function form)

Index Management

FunctionDescription
vector_index_create(index_name, source_table, vector_col, id_col, n_lists, n_probes, metric)Register an IVFFlat index
vector_index_rebuild(index_name)Train/retrain index using Lloyd's k-means
vector_index_insert(index_name, id, vec)Insert one vector into a trained index
vector_index_search(index_name, query, k, n_probes)ANN search; returns (entry_id, distance)
vector_index_stats(index_name)Show index metadata and training status

Examples

-- Create a product embeddings table
CREATE TABLE products (
    id        bigserial PRIMARY KEY,
    name      text,
    embedding vector
);

-- Insert data
INSERT INTO products (name, embedding) VALUES
    ('Blue Widget',  '[0.91, 0.12, 0.03, 0.42]'),
    ('Red Widget',   '[0.05, 0.88, 0.11, 0.37]'),
    ('Green Gadget', '[0.44, 0.41, 0.82, 0.09]');

-- Build IVFFlat index (n_lists=2, n_probes=1, L2 metric)
SELECT vector_index_create('prod_emb', 'products', 'embedding', 'id', 2, 1, 'l2');
SELECT vector_index_rebuild('prod_emb');

-- Search for nearest neighbors
SELECT p.name, r.distance
FROM   vector_index_search('prod_emb', '[0.90, 0.10, 0.05, 0.40]'::vector, 3) r
JOIN   products p ON p.id::text = r.entry_id
ORDER  BY r.distance;
Tip After bulk inserts, call vector_index_rebuild() to retrain centroids. For incremental inserts, use vector_index_insert() to assign new vectors to the existing centroids without a full rebuild.

pg_geo v1.0

2D geometry types and spatial operations. All algorithms are decades-old prior art: ray-casting point-in-polygon (Franklin 1970), AABB intersection (Roberts 1963), shoelace area formula (Gauss 1795), Haversine distance.

Install

CREATE EXTENSION pg_geo;

Types

TypeFormatDescription
geo_pointx,y or POINT(x y)2-D point (16 bytes)
geo_bboxxmin,ymin,xmax,ymax or BOX(...)Axis-aligned bounding box (32 bytes)
geo_polygonWKT: POLYGON((x1 y1,...))Variable-length polygon
geo_circlecx,cy,radius or CIRCLE(cx cy r)Circle (24 bytes)

Functions

FunctionDescription
ST_Point(x, y)Construct a geo_point
ST_MakeBox(xmin,ymin,xmax,ymax)Construct a geo_bbox
ST_Distance(a, b)Euclidean distance between two points
ST_DistanceSphere(a, b)Haversine great-circle distance in metres (lon/lat inputs)
ST_Contains(poly, pt)True if polygon contains point (ray-casting)
ST_Within(pt, poly)Alias for ST_Contains with swapped args
ST_Intersects(bbox_a, bbox_b)AABB overlap test
ST_Area(poly)Signed polygon area (shoelace formula)
ST_BoundingBox(poly)Minimum bounding rectangle of a polygon
ST_Buffer(pt, radius)Create a geo_circle from point + radius
a && bBounding-box overlap operator
ST_NearbyPoints(center, radius_m, table, column, limit)Find nearby geo_point rows within radius (metres)

Examples

-- Store location data
CREATE TABLE stores (
    id      bigserial PRIMARY KEY,
    name    text,
    location geo_point
);

INSERT INTO stores (name, location) VALUES
    ('Downtown',  ST_Point(-73.985, 40.748)),
    ('Uptown',    ST_Point(-73.958, 40.800)),
    ('Brooklyn',  ST_Point(-73.990, 40.680));

-- Find stores within 5 km of Times Square
SELECT s.name,
       round(ST_DistanceSphere(ST_Point(-73.985, 40.758), s.location)::numeric / 1000, 2) AS km
FROM   stores s
ORDER  BY km;

-- Point-in-polygon delivery zone check
SELECT name
FROM   stores
WHERE  ST_Contains(
    'POLYGON((-74.0 40.7,-73.9 40.7,-73.9 40.8,-74.0 40.8,-74.0 40.7))'::geo_polygon,
    location
);

-- Bounding box overlap for coarse spatial filter
SELECT name
FROM   stores
WHERE  ST_BoundingBox(
    'POLYGON((-74.0 40.7,-73.9 40.7,-73.9 40.8,-74.0 40.8,-74.0 40.7))'::geo_polygon
) && ST_MakeBox(
    (location).x - 0.05, (location).y - 0.05,
    (location).x + 0.05, (location).y + 0.05
);

pg_ontology v1.0

W3C-compatible RDF-style triple store (Subject-Predicate-Object) with type hierarchy and graph traversal. Implements a context graph for knowledge representation without proprietary algorithms.

Install

CREATE EXTENSION pg_ontology;

Key Functions

FunctionDescription
ontology_assert(subject, predicate, object, confidence)Add an S-P-O triple
ontology_retract(subject, predicate, object)Remove a triple
ontology_query(subject, predicate, object)Query triples; NULL = wildcard
ontology_related(entity, max_depth)Graph traversal from an entity (recursive CTE)
ontology_ancestors(entity)Type ancestors via subClassOf hierarchy
ontology_type_assert(entity, parent_type)Register a type (NULL parent = root)
ontology_subclass(child, parent)True if child is a subtype of parent
ontology_stats()Triple store statistics

Examples

-- Build a small product knowledge graph
SELECT ontology_type_assert('Organization', NULL);
SELECT ontology_type_assert('Company', 'Organization');

SELECT ontology_assert('AlohaDB Inc.', 'rdf:type',   'Company',   1.0);
SELECT ontology_assert('AlohaDB Inc.', 'makes',      'AlohaDB',   1.0);
SELECT ontology_assert('AlohaDB',      'rdf:type',   'Software',  1.0);
SELECT ontology_assert('AlohaDB',      'basedOn',    'PostgreSQL',1.0);

-- Query: what does AlohaDB Inc. make?
SELECT object AS product
FROM   ontology_query('AlohaDB Inc.', 'makes', NULL);

-- Traverse the graph 2 hops from AlohaDB Inc.
SELECT related_entity, predicate, depth
FROM   ontology_related('AlohaDB Inc.', 2)
ORDER  BY depth, related_entity;

-- Type hierarchy check
SELECT ontology_subclass('Company', 'Organization') AS is_subtype;

pg_context v1.0

Entity disambiguation for context-aware search. Maps ambiguous terms (e.g., "Apple") to canonical entities based on domain context, using a pure lookup-table approach with no patented NLP algorithms.

Install

CREATE EXTENSION pg_context;
-- Optionally extend the ontology graph:
-- CREATE EXTENSION pg_ontology;

Key Functions

FunctionDescription
context_register(term, canonical, domain, confidence)Map a term to a canonical entity in a domain
context_alias(canonical, alias)Register an alternate name for an entity
context_resolve(term, domain)Return canonical entity for term in domain
context_disambiguate(terms text[])Batch resolution (uses default domain per term)
context_rerank(results jsonb, entity_filter text)Boost search results matching a canonical entity
context_retract(term, domain)Remove a mapping
context_list()List all context profiles
context_history(term)Audit log for a term

Examples

-- Register context profiles for "apple"
SELECT context_register('apple', 'Apple Inc.',    'technology', 0.95);
SELECT context_register('apple', 'Apple (fruit)', 'food',       0.90);
SELECT context_alias('Apple Inc.', 'AAPL');

-- Context-aware resolution
SELECT context_resolve('apple', 'technology');  -- Apple Inc.
SELECT context_resolve('apple', 'food');        -- Apple (fruit)
SELECT context_resolve('AAPL',  'technology');  -- Apple Inc. (via alias)

-- Integrate with full-text search
SELECT ts_rank(to_tsvector(body), q) AS rank, title
FROM   articles,
       to_tsquery('apple') AS q,
       context_resolve('apple', 'technology') AS entity
WHERE  to_tsvector(body) @@ q
ORDER  BY rank DESC;

pg_intent v1.0

Document intent classification using keyword-frequency scoring and a hierarchical intent registry. No machine learning model is required; classification is performed with a pure SQL keyword-hit-ratio algorithm.

Install

CREATE EXTENSION pg_intent;

Key Functions

FunctionDescription
intent_register(name, description, keywords[], parent)Register an intent with keywords and optional parent
intent_tag(doc_id, content, intent_name)Explicitly tag a document
intent_infer(content)Score text against all intents; returns (intent_name, score)
intent_auto_tag(doc_id, content)Tag document using highest-scoring inferred intent
intent_of(doc_id)Return all intents for a document
intent_find(intent_name)Return all documents tagged with an intent
intent_ancestors(intent_name)Return ancestor intents via hierarchy
intent_stats()Registry statistics

Examples

-- Define intent hierarchy
SELECT intent_register('support',  'Customer support', ARRAY['help','issue','problem'], NULL);
SELECT intent_register('purchase', 'Purchase intent',  ARRAY['buy','price','order','cart'], 'support');
SELECT intent_register('complaint','Complaint',        ARRAY['broken','wrong','refund','bad'], 'support');

-- Classify incoming text
SELECT intent_name, round(score::numeric, 3)
FROM   intent_infer('I want to buy the blue widget, what is the price?')
WHERE  score > 0.1
ORDER  BY score DESC;

-- Auto-tag and retrieve
SELECT intent_auto_tag(42, 'My order arrived damaged, I need a refund');
SELECT intent_name FROM intent_of(42);

pg_python v1.0

Execute Python code directly inside PostgreSQL using the built-in plpython3u procedural language. Supports inline evaluation, versioned script management, argument passing via JSON, and execution history.

Prerequisite

-- PostgreSQL must be compiled with PL/Python3 support.
-- Verify:
SELECT lanname FROM pg_language WHERE lanname = 'plpython3u';

Install

CREATE EXTENSION pg_python;

Key Functions

FunctionDescription
python_eval(code text, args_json text DEFAULT NULL)Execute Python inline; set _result for return value
python_register(script_name, code)Store a versioned Python script
python_exec(script_name, args_json)Execute a registered script
python_list()List all registered scripts
python_get(script_name)Retrieve a script's latest version code
python_history(script_name)Execution history for a script
python_stats()Script and execution statistics

Examples

-- Inline evaluation
SELECT python_eval('_result = str(sum(range(101)))') AS sum_1_to_100;
-- Returns: '5050'

-- Pass arguments as JSON
SELECT python_eval(
    '_args = __import__("json").loads(_args);
     _result = _args["first"] + " " + _args["last"]',
    '{"first": "Aloha", "last": "DB"}'
) AS full_name;

-- Register a reusable script
SELECT python_register('calc_discount', $py$
import json
args  = json.loads(_args)
price = float(args.get('price', 0))
rate  = float(args.get('rate',  0.10))
_result = str(round(price * (1 - rate), 2))
$py$);

-- Execute it
SELECT python_exec('calc_discount', '{"price": 250.00, "rate": 0.15}');
-- Returns: '212.5'
Warning plpython3u is an untrusted language. It can access the file system and network. Grant execution rights only to trusted users. Use PostgreSQL roles and SECURITY DEFINER functions to limit exposure.

pg_unified v1.0

Unified streaming and batch semantics. Streaming events land in an in-database buffer and are exposed through a dynamic UNION ALL view that combines the batch table with unflushed events. No Spark, Delta Lake, or Databricks-specific code.

Install

CREATE EXTENSION pg_unified;

Key Functions

FunctionDescription
unified_register(source, table, schema, view_name)Create unified source and its UNION ALL view
unified_ingest(source, event_data jsonb)Buffer a streaming event
unified_flush(source)Promote buffered events into the batch table
unified_stream_events(source)Return unflushed buffer events
unified_purge(source)Discard unflushed buffer events
unified_drop(source)Remove unified source and its view
unified_list()List all unified sources
unified_stats(source)Ingest and flush statistics

Examples

-- Batch table
CREATE TABLE events (
    id        bigserial PRIMARY KEY,
    user_id   int,
    action    text,
    ts        timestamptz DEFAULT now()
);

-- Register unified source
SELECT unified_register('event_stream', 'events', 'public', 'events_all');

-- Stream events arrive (e.g., from application, Kafka flush, or webhook)
SELECT unified_ingest('event_stream',
    '{"user_id": 1, "action": "login",  "ts": "2025-01-01T10:00:00Z"}'::jsonb);
SELECT unified_ingest('event_stream',
    '{"user_id": 2, "action": "purchase","ts": "2025-01-01T10:01:00Z"}'::jsonb);

-- Query unified view (batch + stream with no latency gap)
SELECT user_id, action, ts FROM events_all ORDER BY ts;

-- Flush to batch table (run periodically or trigger-based)
SELECT unified_flush('event_stream');

pg_pipeline v1.0

DAG-based ETL pipeline orchestration. Tasks are defined with SQL commands and dependency relationships. A background worker applies Kahn's topological sort (1962) to dispatch ready tasks up to a configurable parallelism limit.

Prerequisite

-- Add to postgresql.conf, then restart:
shared_preload_libraries = 'pg_pipeline'

Install

CREATE EXTENSION pg_pipeline;

Key Functions

FunctionDescription
pipeline_create(name, description)Define a named pipeline
pipeline_task_add(pipeline, task_name, command, step_order)Add a SQL task to a pipeline
pipeline_task_depend(pipeline, task, depends_on)Declare a dependency edge
pipeline_run(pipeline_name)Start a pipeline run; returns run_id
pipeline_cancel(run_id)Cancel a running pipeline
pipeline_status(pipeline_name)Status summary for the most recent run
pipeline_list()List all pipelines
pipeline_history(pipeline_name, limit)Past run history
pipeline_advance_ready(run_id)Internal: promote waiting tasks with all deps met

Examples

-- Define a three-stage ETL pipeline
SELECT pipeline_create('daily_etl', 'Daily data processing');

SELECT pipeline_task_add('daily_etl', 'extract',
    'INSERT INTO stage_raw SELECT * FROM source_system WHERE date = current_date',
    1);

SELECT pipeline_task_add('daily_etl', 'transform',
    'INSERT INTO stage_clean SELECT clean_row(r) FROM stage_raw r',
    2);

SELECT pipeline_task_add('daily_etl', 'load',
    'INSERT INTO warehouse SELECT * FROM stage_clean',
    3);

SELECT pipeline_task_depend('daily_etl', 'transform', 'extract');
SELECT pipeline_task_depend('daily_etl', 'load',      'transform');

-- Start a run
SELECT pipeline_run('daily_etl') AS run_id;

-- Monitor
SELECT pipeline_name, status, completed_tasks, total_tasks
FROM   pipeline_status('daily_etl');

pg_kafka v1.0

Inbound Kafka and AWS Kinesis consumer. A background worker polls configured consumers and writes received messages to pg_kafka_messages. Kafka transport uses librdkafka (Apache 2.0). Kinesis uses AWS HTTP API with SigV4 signing (HMAC-SHA256, RFC 2104).

Prerequisite

-- Add to postgresql.conf, then restart:
shared_preload_libraries = 'pg_kafka'

-- For Kafka (optional; Kinesis uses HTTP only):
-- Install librdkafka >= 1.8

Install

CREATE EXTENSION pg_kafka;

Key Functions

FunctionDescription
kafka_consumer_create(name, type, brokers, topic, group_id)Register a Kafka consumer
kinesis_stream_create(name, region, stream_name, config jsonb)Register a Kinesis consumer
kafka_consumer_start(name)Enable polling for a consumer
kafka_consumer_stop(name)Pause polling

Troubleshooting

Extension Does Not Load

Symptom: ERROR: could not open extension control file ".../pg_vector.control": No such file or directory

Cause: The extension files were not installed to the PostgreSQL data directory.

Fix:

## Verify PostgreSQL extension directory
pg_config --sharedir
ls "$(pg_config --sharedir)/extension/" | grep alohadb

## If missing, reinstall:
cd alohadb-20.0/build
sudo ninja install

## On Windows: re-run the installer or manually copy
## C:\Program Files\AlohaDB\20\share\extension\pg_vector.*
## to the PostgreSQL share\extension directory

Shared Library Not Found

Symptom: ERROR: could not load library ".../pg_vector.so": libm.so.6: cannot open shared object file

Fix:

## Linux: update library cache
sudo ldconfig

## macOS: set DYLD_LIBRARY_PATH if needed
export DYLD_LIBRARY_PATH=/usr/local/lib:$DYLD_LIBRARY_PATH

## Windows: ensure the DLL directory is on PATH
set PATH=C:\Program Files\AlohaDB\20\lib;%PATH%

Background Worker Does Not Start

Symptom: Pipeline tasks never advance. Kafka messages are not consumed. Cron jobs do not run.

Cause: The extension is not listed in shared_preload_libraries.

Fix:

## Check postgresql.conf
grep shared_preload_libraries "$PGDATA/postgresql.conf"

## Should include the extension, e.g.:
## shared_preload_libraries = 'pg_pipeline,pg_kafka,pg_cronjobs'

## After editing, restart the server (SIGHUP is NOT sufficient for this setting)
## Linux:
sudo systemctl restart alohadb

## Windows:
net stop alohadb-20 && net start alohadb-20

## macOS:
brew services restart alohadb
Note Changes to shared_preload_libraries require a full server restart. A pg_reload_conf() call or SIGHUP signal is not sufficient.

pg_objectstore: Authentication Failure

Symptom: WARNING: objectstore_s3: HTTP 403 for s3://bucket/key, objectstore_get returns NULL

Possible causes and fixes:

  • Wrong credentials: Re-register with the correct access key and secret.
  • Wrong region: Ensure the "region" field in the config matches the bucket's region.
  • Clock skew: SigV4 requires server time to be within 5 minutes of AWS time. Check SELECT now() and compare to an NTP source.
  • IAM permissions: The access key must have s3:GetObject / s3:PutObject on the bucket.
-- Check NTP sync on Linux
timedatectl status

-- Verify credential is registered
SELECT label, provider FROM objectstore_credential_list();

-- Re-register with corrected config
SELECT objectstore_credential_register('s3', 'prod-s3', '{
    "bucket": "correct-bucket",
    "region": "us-west-2",
    "access_key_id": "CORRECT_KEY",
    "secret_access_key": "CORRECT_SECRET"
}'::jsonb);

Pipeline Tasks Stuck in "waiting" State

Symptom: Tasks remain in waiting status and never progress to ready.

Possible causes:

  • A dependency task failed and is in failed status. The topological sort will not promote downstream tasks when a dependency has failed.
  • The background worker is not running (see background worker troubleshooting above).
  • A circular dependency exists in the DAG.
-- Inspect task run statuses
SELECT t.task_name, tr.status, tr.error_message
FROM   pipeline_task_runs  tr
JOIN   pipeline_runs       pr ON pr.run_id = tr.run_id
JOIN   pipeline_tasks      t  ON t.task_id = tr.task_id
WHERE  pr.run_id = <your_run_id>
ORDER  BY t.step_order;

-- If a task failed, reset it to retry:
UPDATE pipeline_task_runs
SET    status = 'ready', error_message = NULL
WHERE  task_run_id = <failed_task_run_id>;

-- Check for circular dependencies (should return 0 rows)
WITH RECURSIVE dep_check AS (
    SELECT task_id, dep_task_id, ARRAY[task_id] AS path, false AS cycle
    FROM   pipeline_task_deps
  UNION ALL
    SELECT d.task_id, d.dep_task_id,
           c.path || d.task_id,
           d.task_id = ANY(c.path)
    FROM   pipeline_task_deps d
    JOIN   dep_check c ON c.dep_task_id = d.task_id
    WHERE  NOT c.cycle
)
SELECT * FROM dep_check WHERE cycle;
